Four providers, chosen because they answer

Meterix can only show what a provider is willing to report. These four say how much is left, which is a shorter list than it sounds like.

OpenRouter

Account balance, plus spend over the last 90 days.

In dollars

CheaperInference

Account balance, and the balance it auto-recharges at.

In dollars

DeepSeek

Prepaid balance, including any credit that was granted rather than bought.

In dollars

ElevenLabs

A monthly character allowance, so it is counted in characters and kept out of the money total.

Not money

Audited and left out. OpenAI, Anthropic, Groq and AWS Bedrock. None of them reports a balance to an ordinary key. A gateway that speaks a shape Meterix already knows can be added from the command line.

It watches, so you do not have to

Store

A key goes into your keychain

Paste a key once. Meterix checks it against the provider before replacing anything, then hands it to the operating system's keychain. It never reaches the database.

Read

Each provider is read on a timer

Thirty minutes by default, or an interval you set for one provider alone. A provider that rate-limits can be given hours without the others waiting behind it.

Report

The tray shows the worst state

Teal when everything is fine, amber when a balance is under your threshold, copper when a key has stopped working. The icon is the whole status line, so a glance is enough.

What leaves this machine

One request per provider on a timer, and nothing else. That is a claim you should be able to check rather than believe, so it is worth knowing where each part of it lives in the code.

Your keys go to the operating system keychain

A key is stored in the OS credential store, not in Meterix's own file. Before it replaces the key you already had, Meterix spends it on one real balance read, so a typo is refused instead of saved.

The database is one file you can move

It lives at ~/.meterix/meterix.db and it is a single SQLite file. There is no server to run and no cloud copy. Settings shows you the path, and Change folder moves both the database and the export folder somewhere else.

The only requests are the balance reads

Four provider endpoints, plus the base URL of any gateway you add yourself. There is no account, no analytics and no update check. This is the kind of statement that is easy to write and hard to verify, so it is worth saying plainly: there is no analytics, telemetry or updater dependency anywhere in the project.

A key does not have to be stored at all

Set OPENROUTER_KEY in your environment, or the matching variable for any other provider, and Meterix reads it from there instead of asking you to paste anything.

29 MB

The rest of the memory is the webview the window is drawn in.

~100 B

Per reading, so a few megabytes a year at the default rate.

What it does not do

Worth reading before you rely on it. A balance watcher that overstates itself is worse than none.

By design

  • It reads balances. It is not a cost calculator and not a proxy, so nothing you send to a provider goes through it.
  • There is no account, no cloud and no sync. The database is one file on your machine.
  • Four providers to start with, and more by configuration. A gateway that speaks a shape Meterix already understands can be added from the command line. A provider whose API speaks a new shape is still a code change.
  • Open source, under either MIT or Apache-2.0, whichever you prefer.
  • Desktop only. There is no mobile app and no web version.

Not finished yet

  • The installers are not code signed, so Windows shows SmartScreen and macOS asks you to confirm. What each one says is written out in the section below.
  • Dark only. There is no light theme.
  • Windows is the only platform this has been run on. macOS and Linux build, and nobody has launched them yet.
  • There is no auto-update, so a new version means a new download.
  • A DeepSeek account funded in yuan is refused rather than shown, because everything else here is compared against a dollar threshold.

Questions this raises

Do I need an admin key or a billing account?

No. All four providers report a balance to an ordinary key, which is the whole reason they are the four. Providers that need an admin key were audited and left out.

What happens if a key stops working?

The provider is marked rejected and the tray turns copper. Only a rejected key or a forbidden one raises a notification. A network blip is never treated as a broken key, because that would tell you to rotate something that works.

Does it keep checking when I close the window?

Yes. Closing the dashboard hides it; the tray keeps polling on its timer. Quitting is a separate action with its own label, because those are two different things and one button for both is how a tracker stops tracking without telling you.

Can it watch a provider I host myself?

If it speaks a shape Meterix already understands, yes, from the command line. A local gateway over plain HTTP is allowed for exactly that case. An API with a new response shape still needs code.

Where does my history go if I stop tracking a provider?

Nowhere. Switching a provider off stops the requests and keeps every reading it already collected, so turning it back on does not leave a gap in the chart.

Two things have to be present on Linux. The tray icon needs an AppIndicator host the system can see, and storing a key needs a Secret Service. On a minimal install with neither, the app runs but has no icon and cannot save a key. The AppImage is the one that needs no installer at all: make it executable and run it.

Or build it from source

Rust 1.85 or newer, Node 22 or newer, and WebView2, which Windows 11 already has. Nothing needs OpenSSL. 

# build and run
git clone https://github.com/KrishT0/Meterix
cd Meterix/app
npm install
npm run tauri dev

# release build
npm run tauri build

Use npm run tauri build rather than a plain cargo build. A bare release build produces a binary that loads the development server, so it opens an error page with no JavaScript running at all. It looks like it worked.
