The empty dashboard

With no keys stored, everything below the key field is hidden: the provider cards, the chart and the readings table are all gated on configured.length > 0. So the only thing on the screen is one centred card. Three ways to say the same thing without parking a box in the middle of an empty page.

What is there now

the complaint

A centred card with 36px of vertical padding, floating in a region that is otherwise empty. The text is centred and the block is centred, so it reads as a placeholder rather than something the app is actually saying. Nothing else competes with it, which is why the emptiness is more noticeable than the message.

A — Toast in the corner

recommended

Same words, same mark as the tray icon, pinned bottom-right where a notification belongs. Left-aligned text, no centring, nothing in the middle of the page.

It does not fade. This is the only instruction on the screen, and a first-run user who looks away for eight seconds would be left with an empty dashboard and no hint. It stays until a key is saved, then disappears for good. The close button is there because the panel is dismissing a message, not hiding a control the user needs later.

C — An inline note, not a toast

cheapest

Not a toast at all. The same inset row the dashboard already uses for its note about basis = usage, left-aligned and in the normal flow, so it cannot be dismissed and cannot float over anything.

This is honest about what the block is: a persistent explanation, not a notification. Pick this if the "toast" part of the request mattered more for it not being centred than for it being a toast.

What each costs to build

There is no in-app toast component anywhere in app/src — the only toasts in the project are Windows ones from the notification plugin. A and B therefore introduce a small one.

A is the cheapest of the two: one element rendered when configured.length === 0, absolutely positioned inside the existing scroll container, plus a dismissed flag. No host, no queue, no stacking, no animation — one message in one place.

B adds a timer and the dismissed state has to survive re-renders, so it needs the timeout to be cleaned up properly. Same result on screen, more moving parts.

C adds no machinery at all and reuses markup that already exists on this screen.

The tray mark is drawn grey rather than amber in every option. With nothing configured the tray icon is COLOUR_IDLE (the same grey) and the status line reads idle, so amber would claim a warning where there is only an unconfigured app.
